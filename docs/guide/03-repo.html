The project is a monorepo: one folder containing several small projects that depend on each other.

3.2 Why split it this way

apps/ holds things you run. packages/ holds things that are imported. The arrows below mean "imports from":

Why it is built this wayThe browser and the server must agree exactly on the bytes they exchange. If each had its own copy of that code, one day someone would change one and forget the other. By keeping the message format in packages/shared and importing it from both sides, the two can never drift apart. And the web app has no access to the database package at all, so it cannot accidentally talk to Postgres.

3.4 Two styles of code, on purpose

The server is written with classes. Each class has one named job (for example HeartbeatManager only detects dead connections) and receives the other objects it needs through its constructor. This makes each piece easy to explain and easy to test on its own.

The web app is written with React function components and hooks, which is the normal modern React style. Two pieces of logic that have nothing to do with React, the connection state machine and the retry timing, are plain classes there too, so they can be tested without a browser.
