Part 6The web app

apps/web is a Next.js application. It has three pages, one API route, and a layer of code that keeps a WebSocket alive and a local document in step with the server.

6.1 Server components and client components

In Next.js a component runs either on the server (producing HTML) or in the browser. A file that starts with 'use client' runs in the browser and can use state, effects and WebSockets. Everything else runs on the server.

The room page uses both. page.tsx runs on the server: it asks the sync server "does this room exist?" and shows a proper 404 page if not. If it does, it renders RoomClient.tsx, which runs in the browser and does all the live work.

6.2 src/realtime/: the live layer

FileWhat it does
ConnectionManager.tsA plain class (no React). It owns the WebSocket and implements the connection state machine below: connect, wait for AUTH_ACK, exchange state vectors, then relay updates both ways. It sends a ping every 5 seconds to measure latency, declares the link dead after 20 seconds of silence, and reconnects with growing delays.
ExponentialBackoff.tsComputes the delay before each reconnect attempt: 0.5 s, 1 s, 2 s, 4 s … up to 15 s, with a little randomness so that a thousand clients dropped by one deploy do not all return in the same instant.
protocolCodec.tsThe browser's wrapper around the shared Codec, plus helpers to put a timestamp in a ping.
useYjsDoc.tsA hook that creates the local Yjs document for a room and destroys it when you leave.
useAwareness.tsCreates the awareness object, publishes your name and colour into it, and copies the list of people present into the presence store whenever it changes.
useConnection.tsStarts a ConnectionManager when the component appears and stops it when it disappears. It is deliberately thin: the logic lives in the class.
useRoomSettings.tsThe room's language and title live in a shared map inside the Yjs document. This hook reads them into the editor store and returns functions to change them. Because they are part of the document, changing the language syncs to everyone and is saved, with no extra code.
useEditToken.tsReads the edit token from the part of the URL after #.
useLocalUser.tsYour display name: a random friendly one on first visit, remembered in the browser, editable.

6.3 src/editor/: Monaco

FileWhat it does
monacoSetup.tsOne-time setup: tells Monaco how to start its background workers, defines the light and dark colour themes, and turns off "cannot find module" errors (a shared scratch file has no project around it).
useMonacoEditor.tsCreates one Monaco editor inside a <div> and disposes it on leaving. Changes of language, theme or read-only state are applied to the existing editor, so the cursor and scroll position are kept.
useYMonacoBridge.tsCreates the MonacoBinding from the y-monaco library. This is the bridge: your keystrokes become Yjs operations, remote operations become editor edits, and selections travel through awareness.
EditorView.tsxThe component that puts those hooks together and reports the cursor position to the status bar.

6.4 src/stores/: shared state

A store is a small box of state that any component can read and that re-renders the component when the value changes. There are four:

StoreHoldsRead by
connectionStoreConnection state, latency, permission, which node you are on, any fatal errorStatus bar, disconnect banner
editorStoreCurrent language, title, cursor positionTop bar, status bar, editor
presenceStoreThe list of people in the roomAvatars, remote cursors
themeStoreLight or darkTheme toggle, editor

6.6 How the room page assembles itself

RoomClient.tsx is short because each hook does one thing. In order:

const { ready, token } = useEditToken()          // read #t=… from the URL
const { name, rename } = useLocalUser()          // "Swift Otter"
const doc       = useYjsDoc(room.slug)           // an empty local document
const awareness = useAwareness(doc, name)        // presence, with my name in it
useConnection(wsUrl(slug, token), doc, awareness) // connect and keep in sync
const settings  = useRoomSettings(doc, room)     // language and title

Until the server has confirmed write permission, the editor is read-only. Until the first sync has finished, a "Joining room" placeholder is shown instead of an empty editor that would then jump.
