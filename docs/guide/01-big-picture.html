Part 1The big picture

SyncCode is a code editor that several people can type into at the same time, from different computers, and all see the same text and each other's cursors, instantly.

1.1 What a user sees

  1. You open the website and press Start a room.
  2. You land in an empty code editor. The address bar holds a long link.
  3. You send that link to a friend. They open it and appear in the corner as a coloured circle.
  4. You both type. Each of you sees the other's text appear character by character, and a coloured cursor with their name.
  5. If your wifi drops, you keep typing. When it returns, your changes and theirs are merged.
  6. If you share the link without its last part, the other person can watch but cannot type.

There are no accounts and nothing to install. That is the whole product. Everything else in this guide explains how those six lines are made true.

1.2 Why this is hard

A normal website works like a letter: you send a request, the server sends a reply, done. A shared editor breaks that model in three ways.

Problem 1: the server must talk first

When your friend types, your browser must be told, even though you did not ask anything. Request-and-reply cannot do that. We need a connection that stays open in both directions.

Problem 2: two people can edit the same spot

Imagine the text is AB. You insert x between A and B. At the same instant, your friend inserts y between A and B. Each of you already sees your own change on screen. What should the final text be, AxyB or AyxB? Either is fine, but both screens must agree, and neither keystroke may be lost. Messages cross on the network, arrive late, or arrive twice. Getting every copy to agree anyway is the central problem.

Problem 3: one server is not enough

A real service runs several copies of its server program, so it can survive a crash and handle more users. But if you are connected to server A and your friend to server B, how does your keystroke get to them?

1.4 The architecture in one picture

There are four kinds of program running:

  • The web app (apps/web) serves the pages: the landing page, the editor page, the engineering page. It runs in the browser and, for a few things, on a small server of its own.
  • Sync nodes (apps/sync) are the heart. Each one accepts WebSocket connections, keeps the documents people are currently editing in memory, and passes edits around. You can run one or many; they are identical.
  • Redis is a tiny, very fast message board. Sync nodes use it only to tell each other "this room just changed". Nothing is stored there.
  • Postgres is the database. It is the only place where documents live permanently.

1.5 One keystroke, end to end

You are connected to node A. Your friend is connected to node B. You press x.

  1. Your editor records the change. The editor (Monaco) is bound to a Yjs document living in your browser. Yjs produces a tiny binary description of the change, about 20 bytes, called an update.
  2. The update travels to node A. Your browser puts a 3-byte header in front of it and sends it down the open WebSocket.
  3. Node A applies it. Node A has its own copy of the document in memory. It applies the update, and puts it on a list of things to save.
  4. Node A announces it. It publishes the update on the room's Redis channel, stamped with node A's own id.
  5. Redis delivers it to every node holding that room, including back to node A. Node A sees its own stamp and ignores it.
  6. Node B applies it and sends it to your friend. Your friend's browser applies the update; the x appears on their screen.
  7. Within half a second, node A saves it. All the updates collected in the last 500 ms are written to Postgres in one go.

Measured on a laptop with 50 simulated users spread over two nodes, steps 1 to 6 take a median of 1.7 milliseconds.

In plain wordsEvery browser and every server holds its own copy of the document. An edit is a small note saying "I inserted this, right after that". Notes are passed along until everyone has them. Because of how the notes are designed, everyone who has the same set of notes has the same document.
