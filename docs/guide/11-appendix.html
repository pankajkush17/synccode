D. Glossary

TermMeaning
AwarenessYjs's mechanism for short-lived state such as cursors and names. Not saved.
BackpressureWhat happens when a receiver is slower than the sender, and data piles up.
CapabilityA secret that grants permission to whoever holds it, like a key.
CompactionReplacing many small update rows with one snapshot.
ConvergenceAll copies ending up identical once they have seen the same edits.
CRDTA data structure whose copies can always be merged automatically.
DebounceWaiting briefly to batch many events into one action.
Dependency injectionGiving a class the objects it needs, rather than having it create them.
Echo suppressionA server ignoring its own message when the bus sends it back.
EvictionRemoving an idle room from a server's memory.
FragmentThe part of a URL after #. Never sent to servers.
HMACA fingerprint of a message that can only be produced with a secret key.
Horizontal scalingHandling more load by adding more servers, not a bigger one.
HydrationRebuilding an in-memory object from stored data.
IdempotentDoing it twice has the same effect as doing it once.
MigrationA versioned change to the database's structure.
MonorepoOne repository containing several related projects.
Origin (Yjs)A label on a change saying where it came from.
Pub/subPublish/subscribe: senders post to a channel; all listeners receive.
Repository (pattern)A class that owns all reads and writes for one table.
SlugThe short id of a room that appears in its URL.
SnapshotThe whole document stored as one update.
State vectorA compact summary of which edits a copy has seen.
Stateless serverA server whose memory is only a cache; it can be replaced at any time.
TombstoneThe marker left behind by a deleted item.
Update (Yjs)A small block of bytes describing a change to a document.
WebSocketA connection that stays open so both sides can send at any time.

E. A reading order for the code

If you want to read the source after this guide, this order builds understanding fastest:

  1. packages/shared/src/protocol/Codec.ts and MessageType.ts — the wire format, 60 lines.
  2. apps/sync/src/testing/ProtocolClient.ts — a complete client in 150 lines; the handshake in one place.
  3. apps/sync/src/rooms/Room.ts — the heart of the server.
  4. apps/sync/src/rooms/RoomBroadcaster.ts and RoomManager.ts — fan-out and lifecycle.
  5. apps/sync/src/pubsub/RedisPubSub.ts — the bus and echo suppression.
  6. apps/sync/src/persistence/CompactionJob.ts — the trickiest piece of database logic.
  7. apps/sync/src/SyncServer.ts — how everything is wired.
  8. apps/sync/test/e2e-protocol/convergence.test.ts — the proof.
  9. apps/web/src/realtime/ConnectionManager.ts — the browser side of the same protocol.
  10. apps/web/app/r/[slug]/RoomClient.tsx — how the page assembles it.

F. What to study next

  • The Yjs documentation, especially the pages on the sync protocol and the awareness protocol.
  • The YATA paper: "Near Real-Time Peer-to-Peer Shared Editing on Extensible Data Types". Short and readable.
  • Martin Kleppmann's talk "CRDTs: The Hard Parts".
  • The Redis documentation page on pub/sub. One page, complete.
  • The project's own docs/ folder: architecture.md, crdt-notes.md, scaling-walkthrough.md.
