Part 4The shared packages

Two small packages hold the things more than one program must agree on: the message format, and the shape of the database.

4.1 packages/shared: the contract

packages/shared/src/
├── protocol/
│   ├── MessageType.ts     the eight kinds of message, as numbers 0–7
│   ├── Codec.ts           turns (type, roomRef, payload) into bytes and back
│   └── MessageSchema.ts   shapes of the small control messages + close codes
├── auth/
│   └── TokenShape.ts      what an edit token looks like (types and a pattern only)
├── color/
│   └── ColorPalette.ts    picks a cursor colour from an id, the same everywhere
├── rooms/
│   ├── Languages.ts       the 16 supported languages
│   └── RoomSchema.ts      room ids, API request/response shapes, document key names
└── index.ts               re-exports everything above

MessageType.ts

An enum giving each kind of message a number. That number is the first byte of every frame on the wire.

NumberNameMeaning
0SYNC_STEP_1"Here is my state vector."
1SYNC_STEP_2"Here is what you were missing."
2UPDATE"A new edit just happened."
3AWARENESS"Someone's cursor or presence changed."
4AUTH_ACKServer to client: "you are in; here is your permission."
5ERRORServer to client: "that was not allowed", sent just before closing.
6 / 7PING / PONGClient measures the round-trip time.

MessageSchema.ts

Two of the message types carry a tiny JSON object instead of raw bytes. Zod schemas describe them, and the ControlPayload class converts them to and from bytes:

AUTH_ACK   { permission: "read" | "write", nodeId: "sync-a" }
ERROR      { kind: "protocol", message: "write on read-only socket" }

It also defines the close codes, the number a WebSocket carries when it closes. Codes 4400, 4401 and 4404 mean "do not bother reconnecting" (protocol violation, bad token, no such room). Anything else means "try again".

TokenShape.ts, ColorPalette.ts, Languages.ts, RoomSchema.ts

  • TokenShape: an edit token is exactly 43 URL-safe characters. Only the shape lives here. The code that creates and checks tokens stays on the server, so the browser can never forge one.
  • ColorPalette: eight colours and a small hash function. Give it any id and it always returns the same colour, so everyone sees a given person in the same colour without coordinating.
  • Languages: the list shown in the language picker, plus isLanguageId() to check a value is one of them.
  • RoomSchema: a room id (slug) is 10 lowercase letters or digits. This file also defines the shapes of the HTTP API (CreateRoomRequest, CreateRoomResponse, RoomMeta) and DocKeys, the names used inside every Yjs document: content for the text and meta for the room's language and title.

4.2 packages/db: the database definition

packages/db/
├── schema/
│   ├── bytea.ts               teaches Drizzle about Postgres's binary column type
│   ├── rooms.ts               table: rooms
│   ├── documentUpdates.ts     table: document_updates
│   ├── documentSnapshots.ts   table: document_snapshots
│   └── index.ts
├── migrations/
│   └── 0000_cute_killraven.sql   the SQL that creates the three tables
├── drizzle.config.ts          settings for the migration generator
├── migrate.ts                 small program: apply pending migrations
└── index.ts                   createDb(url) and runMigrations(url)

Each schema file describes one table in TypeScript. From those descriptions Drizzle does two things: it generates the SQL that creates the tables (a "migration"), and it gives the rest of the code typed queries, so a typo in a column name is a compile error rather than a runtime crash.

index.ts exports createDb(url), which opens a pool of connections to Postgres, and runMigrations(url), which applies any migration not yet applied. Part 7 covers the tables themselves in detail.
